# Decisions

## Sanity CMS
- Content (projects, tools, insights, team members, client reviews) comes from Sanity project `ce31dig5`, dataset `production`. Edit content in Sanity, not in `src/components/*/data.ts` — those files now only hold interface copy.
- The Studio is standalone in `techflow-cms/studio`, deliberately **not** embedded in the Next.js app. Studio labels are in English.
- FR/EN are separate documents linked by `@sanity/document-internationalization`; French is the base language. Desk structure (`techflow-cms/studio/structure.ts`) groups projects, tools and insights in folders with French/English sub-lists; creating from a sub-list uses the `<type>-<lang>` template. Languages live in `languages.ts`.
- Content was imported from the live Webflow site (techflow-agency.com) with `pnpm import:live` in the studio. Re-runnable, matches on `sourceUrl`; `-- --only=team` / `-- --only=review` for a single type. One project from the Webflow staging (keeps the live `sourceUrl`, Studio-only fields and list order): `-- --only=project --slug=kretz-club --lang=fr --from=https://techflow-agency-staging.webflow.io`. Staging is French only (English came from Weglot on the live domain).
- `insight.author` references a `teamMember`; empty means "TechFlow Agency". `teamMember` fields: name, role, photo, linkedin, order.
- Project header images mirror Webflow: `heroImage` + `heroSide1`–`heroSide8`. Queries rebuild the 3×3 mosaic as `gallery`; card hover stacks use `previews` = hero + sides 1–2.
- Detail pages pass `alternates` (from `translationLinks`) to `PageShell` so the language switch keeps the translated slug.
- Sectors include "Growth Marketing" (`sector-<lang>-growth-marketing`, added 2026-10-02 by `scripts/add-growth-sector.ts`), first on G.A.T.O Tower before its real-estate sector; it gives growth work its own filter on /projets and the home Work section.
- Project sectors and article categories are `sector` / `category` documents (FR + EN, linked like projects; Studio folders "Sectors" and "Article categories"). Projects pick one or more (`sectors`), articles one or more (`topics`, shown as "Categories" in the Studio), like Tools, limited to the document's language. The old free-text fields (`sector`, `categories`) are hidden and unused, kept only while the Vercel deployment runs code that reads them. Queries return names (`sectors`, `sector` = first one, `categories`), so components get plain strings; listing filters (/projets, /nos-insights, home Work) take their buttons from the lists (`filterOptions` in `page/filters.ts`, entries in use only). One-off migration from the old free text: `scripts/migrate-taxonomies.ts` (already run with `--projects-keep-text`). After the next push: run it without flags to unset the old text, then delete the hidden `sector` / `categories` fields.
- FAQs are `faq` documents, one per page (`home`, `services`, `design`, `development`, `aiAgents`, `salesFunnel`) and language; Studio folder FAQ → one sub-folder per page. Pages fetch `FAQ_QUERY` and pass it to `Faq`, which renders nothing if the FAQ is missing or empty. Add a page: add it to `FAQ_PAGES` (`schemaTypes/documents/faq.ts`) and fetch it in the page.

# Gotchas
- Publishing an old Studio draft replaces the whole published document with it: on 2026-10-02 three projects (Place des Aînés, Épargne Plurielle Avenir, OPCO EP) were published from drafts made on 2026-10-01 before the sector migration and colour seeding, and lost their `sectors` and `accentColor` (restored by script). Scripts patch published documents only; if a document has a draft, discard it or re-check those fields before publishing it.
- Pages cache Sanity results for 60 s (`sanityFetch` revalidate), including a `null`. A page requested just before its document was created keeps 404ing until the cache revalidates (one more request after 60 s); it isn't a code bug.
- Motion's `useScroll({ target })` gave wrong progress for the pinned funnel (it stayed on the last stage); `FunnelSteps` measures the section's `getBoundingClientRect()` on each `scrollY` change instead.
- Webflow, n8n, HubSpot and Twenty logos in `public/images/tools` are white: always show tool logos on their brand colour (`tools` in `services/hub-data.ts`, `TOOLS` in `site/convictions.tsx`), never on a white tile. The /services "Design + development" pipeline's SEO step uses `seo.png` (a stock "SEO" logo from img.magnific.com, a Freepik premium vector, licence to confirm) from `badges` in `hub-data.ts`: pipeline-only, kept out of the toolbox grid; `wide` makes it fill most of the tile.
- The import replaces whole project documents (`createOrReplace`). Fields only set in the Studio must be listed in `STUDIO_ONLY` in `import-live.ts` (today: `logoFill`, `accentColor`) or a re-import erases them.
- The Studio has its own `postcss.config.mjs` (empty): without it Vite walks up to the site's Tailwind PostCSS config and the CI build fails.
- After any schema or query change, run `pnpm typegen` in `techflow-cms/studio`; it writes `sanity.types.ts` at the repo root.
- Video testimonials (`MuxCard`, `page/ui.tsx`): Mux serves these videos **only as HLS** (`stream.mux.com/<id>.m3u8`); MP4 renditions (`medium.mp4`…) return 404, so a plain `<video src=…mp4>` never played (it only showed the poster). They play through `@mux/mux-video-react` (a `<video>` with HLS, `capRenditionToPlayerSize`, Mux Data tracking off). Silent muted loop while on screen (stream attached only near the viewport; carousels render each card up to 10×); the small blue button restarts the same video from 0 with sound; while it talks, a click pauses it and the button returns; one video with sound at a time (`techflow:video-sound` event); the carousel row stops while one talks (`has-[[data-playing]]`). MuxVideo's `autoplay` prop leaks onto the DOM, so autoplay is set on the element through the ref. Verifying playback needs a visible browser (a hidden preview pane doesn't decode video).
- Reduced motion: use `useStill()` (`site/use-still.ts`), never Motion's `useReducedMotion()`. Motion's hook reads the OS setting during the first browser render while the server assumes "no preference", so with Reduce motion on (macOS Accessibility) every `initial`/style that depends on it differs from the server HTML: "A tree hydrated but some attributes … didn't match". `useStill` is false on the server and during hydration, then the real setting.
- `<Testimonials />` is an async server component, so client pages receive it as a `testimonials` slot prop — don't import it directly into a client component.
- 3D wall effects: in Chrome a `mask-image` on the same element as `perspective` is ignored, and `transform-style: preserve-3d` breaks hit-testing on the tilted content (clicks land on the column, not the link). Fade with gradient overlays (`z-10` above an `isolate` 3D layer) and keep the tilted layer flat.
- Case-study chapter ids come from the h2 text; ids equal to the page's own anchors (`histoire`, `en-bref`) get a `chapitre-` prefix (`RESERVED` in `cms-case-study-page.tsx`). Add new fixed anchors there.
- Tall images shown whole with `w-auto h-auto max-h-*` have no size until they load, so lazy loading never triggers: cap the width by aspect ratio instead (`VisualBreak`).
- Image lists from the CMS can repeat the same asset (a screen used as hero and side), so don't key React lists by `_key`/asset ref alone.
- `sanity exec` scripts can't load Studio React inputs (`.tsx`): never import `schemaTypes` (or a schema file that imports `components/`) from a script. `import-live.ts` compiles only `blockContent` plus stand-ins.
- Weglot broke some English meta descriptions on the old site (`false"<client quote>…`); `scripts/import-seo.ts` replaced them. Treat any `false"` prefix in imported English text as that bug.
- Performance (PageSpeed, 2026-10-02): a hero's subtitle is usually the page's LCP element. Never start it at `opacity: 0` (it then only counts once the JavaScript has loaded, +2–3 s on mobile): slide it only (`initial={{ y }}`; `rise(delay, false)` / `reveal(delay, false)` in the article and case-study heroes). Hero images aren't `preload`ed when the text above them is the main content on phones. CSS is inlined (`experimental.inlineCss`).
- Client components must never import server Sanity modules (`sanity/client`, `queries`, `seo`, `fetch`) or `next-sanity`: it ships `@sanity/client` (~37 KB gz) to every page. Use `sanity/env` for ids, `@portabletext/react` for rich text, `absoluteUrl` from `i18n/routes`. `not-found.tsx` is a client component rendering `PageShell`, so everything `PageShell` imports is in the browser bundle. Check after a build: `grep -l '@sanity/client' .next/static/chunks/*.js` should print nothing.
- The Mux testimonial player (hls.js, ~300 KB) is a `next/dynamic` import mounted only near the viewport; until then the card shows the Mux thumbnail.
- Lists animated with `FadeIn` use `<FadeIn as="li">` so `<ul>`/`<ol>` keep only `<li>` children (accessibility audit). Muted text on dark backgrounds is at least `text-white/55`, on paper `text-ink/60` (contrast 4.5:1).
- Card hover-stack images (`previews`) are queried without LQIP (`imageNoBlur`): every project's data is serialised into the page, and the blur strings made the home HTML ~165 KB heavier.
- The `AGENTS.md` block is regenerated by `next dev`; put project notes in this file, not there.
